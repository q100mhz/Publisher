# Publisher

Реестр публикаций с дашбордом, парсером новостей и генерацией статей через DeepSeek.
Открывается по адресу `https://itb2bhost.ru/publisher/` и не мешает другим сайтам на домене.

**Стек:** Python 3.12 · FastAPI · PostgreSQL 16 · Playwright (Chromium) · trafilatura · Docker Compose.

## Возможности

- **Вход** по заранее заданному логину и паролю. Регистрации нет.
- **Дашборд:** всего, в работе, опубликовано, отложено, в архиве, «опубликовать сегодня». Есть фильтр периода, каждая плитка открывает свой список.
- **Реестр:** поиск, фильтры по статусу, источнику и дублям, просмотр архива, массовые действия.
  Подсветка строк: **жёлтая** — плановая дата публикации сегодня, **красная** — дата прошла, а новость не опубликована.
- **Карточка новости:**
  - поля: заголовок, дата создания, плановая и фактическая даты публикации, текст оригинала;
  - картинки: несколько штук, показываются миниатюрами, по клику скачивается оригинал;
  - кнопка «Сгенерировать» с выбором промпта;
  - предпросмотр «как увидит читатель», вкладка с HTML-кодом и кнопка «Скопировать код»;
  - версии генерации, отметка «дубль», история изменений.
- **Статусы:** Новая → Сгенерирована → Опубликована / Отложена. «Отклонено» заменено архивом. Удалить запись нельзя, только отправить в архив (и вернуть оттуда).
- **Справочник источников:** адрес, название, необязательный фильтр по ключевым словам, исключение сайта из автопарсинга.
- **Парсер:** рубильник (сразу обходит все сайты, дальше каждые 4 часа) и ручной запуск по каждому сайту. Ручной запуск недоступен, пока включён рубильник.
- **Справочник промптов** с подстановками `{title}`, `{original_text}`, `{source_url}`, `{source_name}`, `{date}`. Один из промптов назначается основным.
- **Журнал парсера:** подробный лог каждого запуска.

## Развёртывание на VPS

Нужны Docker с плагином Compose и nginx, который уже обслуживает itb2bhost.ru.

### 1. Скопировать проект на сервер

```bash
scp -r Publisher root@itb2bhost.ru:/opt/publisher
```

Можно и через git. В любом случае папки `.venv` и `data` на сервер не нужны.

### 2. Заполнить `.env`

```bash
cd /opt/publisher
cp .env.example .env
nano .env
```

Обязательные значения:

| Переменная | Что указать |
|---|---|
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | логин и пароль для входа (см. раздел «Вход») |
| `SECRET_KEY` | результат команды `openssl rand -hex 32` |
| `POSTGRES_PASSWORD` | результат команды `openssl rand -hex 16` |
| `DEEPSEEK_API_KEY` | ключ с platform.deepseek.com |
| `COOKIE_SECURE` | `true`, если сайт работает по https |

### 3. Запустить

```bash
docker compose up -d --build
docker compose logs -f app      # должно появиться «Создан пользователь …»
```

Приложение слушает только `127.0.0.1:8090`, то есть снаружи напрямую недоступно.

### 4. Подключить к nginx по пути `/publisher/`

Скопируйте блоки из `deploy/nginx-publisher.conf` внутрь существующего `server { … }` домена itb2bhost.ru:

```bash
nano /etc/nginx/sites-available/itb2bhost.ru   # путь может отличаться
nginx -t && systemctl reload nginx
```

Проксируется только `/publisher/`, остальные сайты продолжают работать как раньше. Удалять их не нужно.

> Если на сервере Apache, а не nginx, нужны две директивы:
> `ProxyPass /publisher/ http://127.0.0.1:8090/publisher/` и `ProxyPassReverse /publisher/ http://127.0.0.1:8090/publisher/`
> (модули `proxy` и `proxy_http`).

### Обновление

Перед обновлением сделайте резервную копию базы (команда ниже, в разделе «Резервная копия»). Затем:

```bash
cd /opt/publisher && git pull && docker compose up -d --build
```

При запуске приложение само обновляет структуру базы, если это нужно (файл `app/migrate.py`). Данные хранятся в томах Docker `pgdata` (база) и `media` (картинки) и при обновлении не теряются.

### Резервная копия

```bash
docker compose exec -T db pg_dump -U publisher publisher | gzip > backup_$(date +%F).sql.gz
docker run --rm -v publisher_media:/m -v "$PWD":/b alpine tar czf /b/media_$(date +%F).tgz -C /m .
```

## Пользователи и личные кабинеты

У каждого пользователя свой кабинет: свои источники, реестр, промпты, нейросеть с ключом, тема оформления и рубильник автопарсинга. К чужим данным доступа нет ни у кого, включая администратора: чужие записи выглядят как несуществующие.

Самостоятельной регистрации нет. Пользователей заводит **администратор** в разделе «Пользователи»: логин, пароль и, при желании, права администратора. Там же можно сменить пароль, запретить вход (данные при этом сохраняются) или выдать и снять права администратора.

При переходе со старой версии всё, что уже было в системе, закрепляется за первым администратором.

## Вход: как задать логин и пароль

Первый администратор задаётся одним из трёх способов.

1. **При первом запуске** — через `.env`:
   ```
   ADMIN_LOGIN=denis
   ADMIN_PASSWORD=очень-длинный-пароль
   ```
   Если пользователей в базе ещё нет, он будет создан. Пароль сохраняется только в виде хеша bcrypt, поэтому после первого входа строку `ADMIN_PASSWORD` из `.env` можно удалить.

2. **Из консоли сервера** — так можно создать пользователя или сменить пароль в любой момент. Пароль вводится скрыто и в истории команд не остаётся. Первый созданный так пользователь становится администратором.
   ```bash
   docker compose exec app python -m app.cli set-password denis
   ```
   Выдать права администратора существующему пользователю:
   ```bash
   docker compose exec app python -m app.cli make-admin denis
   ```

3. **В интерфейсе:** «Настройки» → «Смена пароля».

Защита входа:
- после 5 неверных попыток с одного IP вход блокируется на 15 минут;
- сессия хранится 30 дней в подписанной cookie (HttpOnly, SameSite=Lax);
- запросы, изменяющие данные, с чужих сайтов отклоняются.

## Как работает парсер

### Какие статьи берутся

- **Новый сайт** (с него ещё ничего не загружали) — 5 последних статей.
- **Повторный запуск** — все статьи, которые на странице-списке стоят выше уже загруженных. Если у статьи есть дата, дополнительно проверяется, что она не старше последней загруженной. Одиночная «закреплённая» статья в самом верху ленты не сбивает границу.
- Ссылка, обработанная однажды, не загружается повторно, даже если запись потом ушла в архив.
- Если для сайта заданы **ключевые слова**, в реестр попадают только статьи, где встречается хотя бы одно из них. Отсеянные тоже запоминаются и повторно не скачиваются.
- **Дубли** одной новости с разных сайтов помечает пользователь — кнопкой «Пометить как дубль» в карточке или массово в реестре.

### Автоизвлечение (без настройки под каждый сайт)

1. Загружается страница-список. Ссылки на статьи распознаются по общим признакам: тот же домен, «человекочитаемый» адрес, общий родительский раздел, и таких ссылок на странице много. Меню, рубрики, теги и пагинация отбрасываются.
2. Если ссылок меньше трёх (лента подгружается скриптом, как у knopka.com на Tilda), страница открывается в настоящем браузере Chromium. Браузер прокручивает страницу и ждёт, пока статьи появятся, но не дольше 20 секунд.
3. Из каждой статьи библиотека trafilatura извлекает заголовок, дату, текст (с абзацами, подзаголовками и списками) и картинки. Если текст получился слишком коротким, статья тоже открывается через браузер.
4. Картинки скачиваются на сервер: оригинал сохраняется без изменений, и для него делается миниатюра. Картинки меньше 150 px (иконки) пропускаются.

Проверено на ваших примерах: moedelo.org/club (обычный HTML) и knopka.com/blog (лента Tilda через браузер).
Указывайте **первую страницу** ленты, без `?page=3`: на ней самые свежие статьи.

### Паузы против блокировок

- Перед каждым запросом к сайту выдерживается случайная пауза **2–5 секунд** с момента предыдущего запроса к **этому же** домену. Разные сайты друг друга не тормозят.
- К одному домену в каждый момент идёт только один запрос.
- Если сайт ответил «429 Too Many Requests» или «503», делается до двух повторов с паузой 10 и 30 секунд или столько, сколько сайт попросил в заголовке `Retry-After` (максимум 60 секунд).
- Запросы выглядят как обычный Chrome: User-Agent и русский `Accept-Language`.

**Скорость.** Одна статья — это запрос страницы и запрос картинки, то есть примерно 4–8 секунд. В тестах с knopka загрузилось 5 статей за 36 секунд вместе с открытием ленты в браузере, с moedelo — 6–8 секунд на статью. Требование «хотя бы 3 статьи в минуту» выполняется с запасом. Один раз при локальной проверке самая первая статья после запуска сервера задержалась примерно на минуту; при повторных запусках это не повторилось. Паузы настраиваются в `.env` (`PARSER_DELAY_MIN` / `PARSER_DELAY_MAX`).

### Рубильник

- **Включение:** сразу запускается обход всех активных сайтов, следующий — через 4 часа. Ручные кнопки «Спарсить сейчас» при этом неактивны.
- **Перезапуск контейнера:** ритм сохраняется. Если последний обход был час назад, следующий начнётся через 3 часа.
- **Один сайт никогда не парсится в двух потоках одновременно.**

## Генерация

1. В карточке выбирается промпт и нажимается «Сгенерировать». Запрос уходит в выбранную нейросеть в фоне: страница не зависает, и её можно закрыть.
2. Ответ (HTML) сохраняется в поле HTML-кода. Предыдущий вариант остаётся в «Версиях генерации», его можно вернуть.
3. Вкладка **«Как увидит читатель»** показывает статью в изолированном окне. Скрипты из ответа нейросети не выполняются. `<title>` и `meta description` показываются отдельной плашкой «SEO».
4. **«Скопировать код»** кладёт в буфер обмена полный HTML. Перед копированием код можно поправить вручную.

### Своя нейросеть и свой ключ

В «Настройках» → «Нейросеть» каждый пользователь выбирает сервис, модель и вставляет свой API-ключ. Кнопка «Проверить подключение» отправляет короткий пробный запрос.

| Сервис | Модели (примеры) | Примечание |
|---|---|---|
| DeepSeek | `deepseek-chat`, `deepseek-reasoner` | |
| OpenAI (ChatGPT) | любая модель из документации OpenAI | |
| Anthropic (Claude) | `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5` | Температура не настраивается. Для Opus и Sonnet включён автоматический повтор запроса на другой модели Claude, если основная откажется отвечать. |
| OpenRouter | сотни моделей по одному ключу | |
| Другой OpenAI-совместимый API | любой | Нужен адрес API. Так подключаются локальные модели и сервисы со шлюзом в формате OpenAI. |

Ключи хранятся в базе в зашифрованном виде (шифрование привязано к `SECRET_KEY` из `.env`). На страницу выводится только маска вида `sk-…1234`. Если сменить `SECRET_KEY`, ключи придётся ввести заново.

`DEEPSEEK_API_KEY` в `.env` необязателен: это общий ключ, которым пользуются только администраторы, пока не указали свой.

Учтите, что API OpenAI и Anthropic из России напрямую не работают: серверу нужен доступ к ним или посредник вроде OpenRouter.

## Можно ли автоматизировать публикацию в Битрикс24 → «Сайты»

**Да, через REST API Битрикс24** (методы `landing.*`). Сейчас это не реализовано. Схема будет такой:

1. **Подготовка (один раз).** На портале создаётся страница-шаблон: шапка, подвал, оформление, а в центре — блок «HTML-код». Создаётся входящий вебхук с правами `landing` (Разработчикам → Другое → Входящий вебхук). Его адрес сохраняется в настройках Publisher вместе с ID сайта и ID страницы-шаблона.
2. **Кнопка «Опубликовать в Битрикс24»** в карточке выполняет:
   - `landing.landing.copy` — копирует шаблон в нужный сайт или папку (например, «База знаний») и получает ID новой страницы;
   - `landing.block.getlist` — находит на новой странице блок «HTML-код»;
   - `landing.block.updatenodes` / `landing.block.updatecontent` — вставляет в этот блок тело статьи;
   - `landing.landing.update` — задаёт название, адрес (ЧПУ) и SEO-поля. `<title>` и `meta description` из ответа DeepSeek переносятся в настройки страницы, а не в тело;
   - `landing.landing.publication` — публикует страницу;
   - сохраняет в реестре ссылку на опубликованную страницу и ставит статус «Опубликована» с сегодняшней датой.
3. **Картинки** загружаются в Диск или медиатеку портала, и ссылки в HTML заменяются на ссылки Битрикс24.

**Что нужно проверить на вашем портале до реализации:**
- насколько Битрикс24 очищает HTML в блоке (часть тегов и атрибутов может вырезаться);
- даёт ли тариф доступ к REST и вебхукам;
- нет ли на системных блоках ограничений на изменение через API.

Если ограничения есть, запасной вариант — собственный блок, зарегистрированный через `landing.repo.register`.

## Локальный запуск (для разработки)

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium
BASE_PATH=/publisher ADMIN_LOGIN=admin ADMIN_PASSWORD=test12345 .venv/bin/uvicorn app.main:app --port 8090 --reload
```

Откройте http://localhost:8090/publisher/. Без `DATABASE_URL` используется SQLite в `data/publisher.db`.

## Структура

```
app/
  main.py            приложение, middleware, запуск планировщика
  config.py          настройки из .env
  models.py          таблицы БД
  auth.py, cli.py    вход, смена пароля из консоли
  routes/            страницы: реестр, карточка, источники, промпты, настройки
  services/
    fetcher.py       загрузка страниц с паузами, браузерный режим
    extractor.py     поиск ссылок на статьи и извлечение текста
    parser.py        логика запуска парсинга
    scheduler.py     рубильник (каждые 4 часа)
    generator.py     запросы к DeepSeek
    images.py        оригиналы и миниатюры
  templates/, static/  интерфейс
deploy/nginx-publisher.conf
Dockerfile, docker-compose.yml, .env.example
```
