# Publisher

Реестр публикаций с дашбордом, парсером новостей и генерацией статей через DeepSeek.
Открывается по адресу `https://itb2bhost.ru/publisher/` и не мешает другим сайтам на домене.

**Стек:** Python 3.12 · FastAPI · PostgreSQL 16 · Playwright (Chromium) · trafilatura · Docker Compose.

## Возможности

- **Вход** по заранее заданному логину и паролю. Регистрации нет.
- **Дашборд:** всего, в работе, опубликовано, отложено, в архиве, «опубликовать сегодня». Есть фильтр периода, каждая плитка открывает свой список.
- **Реестр:** поиск, фильтры по статусу, источнику и дублям, просмотр архива, массовые действия.
  Подсветка строк: **жёлтая** — плановая дата публикации сегодня, **красная** — дата прошла, а новость не опубликована.
- **Карточка новости:**
  - поля: заголовок, дата создания, плановая и фактическая даты публикации, текст оригинала;
  - картинки: несколько штук, показываются миниатюрами, по клику скачивается оригинал;
  - кнопка «Сгенерировать» с выбором промпта;
  - предпросмотр «как увидит читатель», вкладка с HTML-кодом и кнопка «Скопировать код»;
  - версии генерации, отметка «дубль», история изменений.
- **Статусы:** Новая → Сгенерирована → Опубликована / Отложена. «Отклонено» заменено архивом. Удалить запись нельзя, только отправить в архив (и вернуть оттуда).
- **Справочник источников:** адрес, название, необязательный фильтр по ключевым словам, исключение сайта из автопарсинга.
- **Парсер:** рубильник (сразу обходит все сайты, дальше каждые 4 часа) и ручной запуск по каждому сайту. Ручной запуск недоступен, пока включён рубильник.
- **Справочник промптов** с подстановками `{title}`, `{original_text}`, `{source_url}`, `{source_name}`, `{date}`. Один из промптов назначается основным.
- **Журнал парсера:** подробный лог каждого запуска.

## Развёртывание на VPS

Нужны Docker с плагином Compose и nginx, который уже обслуживает itb2bhost.ru.

### 1. Скопировать проект на сервер

```bash
scp -r Publisher root@itb2bhost.ru:/opt/publisher
```

Можно и через git. В любом случае папки `.venv` и `data` на сервер не нужны.

### 2. Заполнить `.env`

```bash
cd /opt/publisher
cp .env.example .env
nano .env
```

Обязательные значения:

| Переменная | Что указать |
|---|---|
| `SECRET_KEY` | результат команды `openssl rand -hex 32` |
| `POSTGRES_PASSWORD` | результат команды `openssl rand -hex 16` |
| `COOKIE_SECURE` | `true`, если сайт работает по https |

### 3. Запустить

```bash
docker compose up -d --build
docker compose exec app python -m app.cli add-user ivan@example.com   # или регистрация на сайте
```

Приложение слушает только `127.0.0.1:8090`, то есть снаружи напрямую недоступно.

### 4. Подключить к nginx по пути `/publisher/`

Скопируйте блоки из `deploy/nginx-publisher.conf` внутрь существующего `server { … }` домена itb2bhost.ru:

```bash
nano /etc/nginx/sites-available/itb2bhost.ru   # путь может отличаться
nginx -t && systemctl reload nginx
```

Проксируется только `/publisher/`, остальные сайты продолжают работать как раньше. Удалять их не нужно.

> Если на сервере Apache, а не nginx, нужны две директивы:
> `ProxyPass /publisher/ http://127.0.0.1:8090/publisher/` и `ProxyPassReverse /publisher/ http://127.0.0.1:8090/publisher/`
> (модули `proxy` и `proxy_http`).

### Админка на publisher-admin.itb2bhost.ru

1. В DNS домена itb2bhost.ru добавьте A-запись `publisher-admin` с IP сервера.
2. На сервере скопируйте `deploy/nginx-publisher-admin.conf` в `/etc/nginx/sites-available/publisher-admin`, сделайте ссылку в `sites-enabled`, выполните `nginx -t && systemctl reload nginx`, затем `certbot --nginx -d publisher-admin.itb2bhost.ru --redirect`.
3. В `.env` укажите `ADMIN_HOST=publisher-admin.itb2bhost.ru` и создайте администратора: `docker compose exec app python -m app.cli add-admin <логин>`.

### Обновление

Перед обновлением сделайте резервную копию базы (команда ниже, в разделе «Резервная копия»). Затем:

```bash
cd /opt/publisher && git pull && docker compose up -d --build
```

При запуске приложение само обновляет структуру базы, если это нужно (файл `app/migrate.py`). Данные хранятся в томах Docker `pgdata` (база) и `media` (картинки) и при обновлении не теряются.

### Резервная копия

```bash
docker compose exec -T db pg_dump -U publisher publisher | gzip > backup_$(date +%F).sql.gz
docker run --rm -v publisher_media:/m -v "$PWD":/b alpine tar czf /b/media_$(date +%F).tgz -C /m .
```

## Пользователи и личные кабинеты

У каждого пользователя свой отдельный кабинет: источники, реестр, промпты, нейросети с ключами, тема и рубильник автопарсинга. Кабинеты не пересекаются: чужие записи выглядят как несуществующие.

- **Только e-mail:** пользователи регистрируются, входят и создаются из терминала только по e-mail. Обычные логины не допускаются. Старые учётные записи с логином переводятся на e-mail командой `set-email` или в админке — до этого войти они не смогут (в админке такие помечены «нет e-mail»).
- **Регистрация:** любой может зарегистрироваться по e-mail и паролю на странице входа (`/publisher/register`) и сразу работать. Нейросеть он подключает своим ключом, либо вы разрешаете ему базовый ключ DeepSeek в админке.
- **Защита регистрации:** не больше 5 регистраций в час с одного IP и скрытое поле-ловушка для ботов. Отключить регистрацию: `REGISTRATION_ENABLED=false` в `.env`.
- **Подтверждения почты и восстановления пароля пока нет:** забытый пароль сбрасывает администратор.

Команды терминала (после `docker compose exec app python -m app.cli`):

| Задача | Команда |
|---|---|
| Создать пользователя | `add-user <e-mail>` |
| Сменить пароль | `set-password <e-mail>` |
| Заменить старый логин или e-mail на новый e-mail | `set-email <старый> <e-mail>` |
| Запретить / разрешить вход | `disable-user <e-mail>` / `enable-user <e-mail>` |
| Список пользователей | `users` |
| Создать администратора | `add-admin <логин>` |
| Сменить пароль администратора | `admin-password <логин>` |
| Список администраторов | `admins` |

Защита входа:
- 5 неверных попыток с одного IP — блокировка на 15 минут;
- сессия хранится 30 дней в подписанной cookie;
- заблокированного пользователя выкидывает из уже открытой сессии;
- запросы с чужих сайтов отклоняются.

## Админка — https://publisher-admin.itb2bhost.ru

Вход — отдельными учётными записями администраторов. Они создаются только из терминала (`add-admin`) и с пользователями не связаны. Содержимое кабинетов (новости, тексты) админка не показывает — только учётные данные и статистику.

- **Дашборд:**
  - пользователи: всего, новые за 7 и 30 дней, активные, заблокированные;
  - подключено источников и спарсено статей;
  - генерации за сегодня и за 30 дней, доля ошибок, использование базового DeepSeek;
  - графики регистраций и обращений к нейросетям по дням;
  - разбивка по сервисам и самые активные пользователи;
  - здоровье системы: свободное место на диске, размер базы и картинок, источники с ошибками парсинга, последние ошибки нейросетей.
- **Пользователи:**
  - поиск и фильтры, у каждого: число источников, спарсенных статей, новостей и генераций;
  - массовое включение и выключение доступов.
- **Карточка пользователя:**
  - смена e-mail (только корректный e-mail);
  - новый пароль или временный пароль (показывается один раз);
  - завершение всех сессий, блокировка;
  - доступы: базовый DeepSeek с месячным лимитом и публикация в Битрикс24.
- **Журнал действий:** кто из администраторов и что менял.
- **Объявление:** полоса вверху всех кабинетов (информация — жёлтая, важное — красная).

**Базовый ключ DeepSeek** задаётся в `.env` (`DEEPSEEK_API_KEY`). Правила:
- работает, только если вы разрешили его пользователю;
- если у пользователя есть свой ключ DeepSeek, используется свой — даже при разрешении;
- удалил свой ключ или выбрал DeepSeek без ключа — снова работает базовый;
- лимит считает только успешные генерации через базовый ключ в текущем месяце.

## Защита от инъекций и атак через поля ввода

- **SQL-инъекции** (`'q=1`, `' OR 1=1 --`, `UNION SELECT…`) невозможны: все запросы к базе идут через SQLAlchemy с параметрами, введённый текст никогда не становится частью SQL. В поиске `%` и `_` ищутся как обычные символы.
- **XSS:** все шаблоны экранируют вывод. Статья от нейросети показывается в изолированном окне без скриптов. Из ответа нейросети вырезаются `<script>` (кроме разметки schema.org), `<iframe>`, формы, обработчики `on…=` и ссылки `javascript:`.
- **CSP и заголовки безопасности:**
  - разрешены только свои скрипты — встроенных и чужих нет;
  - сайт нельзя встроить в чужую страницу;
  - `nosniff`, `Referrer-Policy`, HSTS при работе по https;
  - страницы с личными данными не кешируются.
- **SSRF.** Адреса источников, API нейросетей, ссылок на картинки и вебхуков Битрикс24 проверяются: запросы во внутреннюю сеть сервера запрещены. Это касается `127.0.0.1`, `localhost`, `10.*`, `192.168.*`, `169.254.169.254`, имён docker-сервисов вроде `db`, а также доменов, которые указывают на такие адреса. Проверяется и каждое перенаправление, и каждый ресурс в браузерном режиме парсера.
- **Ввод:** длина полей ограничена, управляющие символы вырезаются, имена загружаемых файлов очищаются от путей, кавычек и переводов строк.
- **Промпты:** нейросеть получает указание считать текст статьи материалом, а не командами. Персональные данные удаляются до отправки.
- **CSRF:** изменяющие запросы с чужих сайтов отклоняются, cookie — `HttpOnly` и `SameSite=Lax`.

Для локальной разработки с заглушками на `127.0.0.1` можно задать `ALLOW_PRIVATE_URLS=true`. На сервере эту переменную не задавайте.

## Как работает парсер

### Какие статьи берутся

- **Новый сайт** (с него ещё ничего не загружали) — 5 последних статей.
- **Повторный запуск** — все статьи, которые на странице-списке стоят выше уже загруженных. Если у статьи есть дата, дополнительно проверяется, что она не старше последней загруженной. Одиночная «закреплённая» статья в самом верху ленты не сбивает границу.
- Ссылка, обработанная однажды, не загружается повторно, даже если запись потом ушла в архив.
- Если для сайта заданы **ключевые слова**, в реестр попадают только статьи, где встречается хотя бы одно из них. Отсеянные тоже запоминаются и повторно не скачиваются.
- **Дубли** одной новости с разных сайтов помечает пользователь — кнопкой «Пометить как дубль» в карточке или массово в реестре.

### Автоизвлечение (без настройки под каждый сайт)

1. Загружается страница-список. Ссылки на статьи распознаются по общим признакам: тот же домен, «человекочитаемый» адрес, общий родительский раздел, и таких ссылок на странице много. Меню, рубрики, теги и пагинация отбрасываются.
2. Если ссылок меньше трёх (лента подгружается скриптом, как у knopka.com на Tilda), страница открывается в настоящем браузере Chromium. Браузер прокручивает страницу и ждёт, пока статьи появятся, но не дольше 20 секунд.
3. Из каждой статьи библиотека trafilatura извлекает заголовок, дату, текст (с абзацами, подзаголовками и списками) и картинки. Если текст получился слишком коротким, статья тоже открывается через браузер.
4. Картинки скачиваются на сервер: оригинал сохраняется без изменений, и для него делается миниатюра. Картинки меньше 150 px (иконки) пропускаются.

Проверено на ваших примерах: moedelo.org/club (обычный HTML) и knopka.com/blog (лента Tilda через браузер).
Указывайте **первую страницу** ленты, без `?page=3`: на ней самые свежие статьи.

### Паузы против блокировок

- Перед каждым запросом к сайту выдерживается случайная пауза **2–5 секунд** с момента предыдущего запроса к **этому же** домену. Разные сайты друг друга не тормозят.
- К одному домену в каждый момент идёт только один запрос.
- Если сайт ответил «429 Too Many Requests» или «503», делается до двух повторов с паузой 10 и 30 секунд или столько, сколько сайт попросил в заголовке `Retry-After` (максимум 60 секунд).
- Запросы выглядят как обычный Chrome: User-Agent и русский `Accept-Language`.

**Скорость.** Одна статья — это запрос страницы и запрос картинки, то есть примерно 4–8 секунд. В тестах с knopka загрузилось 5 статей за 36 секунд вместе с открытием ленты в браузере, с moedelo — 6–8 секунд на статью. Требование «хотя бы 3 статьи в минуту» выполняется с запасом. Один раз при локальной проверке самая первая статья после запуска сервера задержалась примерно на минуту; при повторных запусках это не повторилось. Паузы настраиваются в `.env` (`PARSER_DELAY_MIN` / `PARSER_DELAY_MAX`).

### Рубильник

- **Включение:** сразу запускается обход всех активных сайтов, следующий — через 4 часа. Ручные кнопки «Спарсить сейчас» при этом неактивны.
- **Перезапуск контейнера:** ритм сохраняется. Если последний обход был час назад, следующий начнётся через 3 часа.
- **Один сайт никогда не парсится в двух потоках одновременно.**

## Генерация

1. В карточке выбирается промпт и нажимается «Сгенерировать». Запрос уходит в выбранную нейросеть в фоне: страница не зависает, и её можно закрыть.
2. Ответ (HTML) сохраняется в поле HTML-кода. Предыдущий вариант остаётся в «Версиях генерации», его можно вернуть.
3. Вкладка **«Как увидит читатель»** показывает статью в изолированном окне. Скрипты из ответа нейросети не выполняются. `<title>` и `meta description` показываются отдельной плашкой «SEO».
4. **«Скопировать код»** кладёт в буфер обмена полный HTML. Перед копированием код можно поправить вручную.

### Изменённый заголовок и META

- **«Изменённый заголовок»** заполняется из `<h1>` сгенерированной статьи, если поле ещё пустое. Ещё его можно сгенерировать отдельно кнопкой «Сгенерировать заголовок» — для неё в «Промптах» есть раздел «Для заголовка».
- **META-раздел.** После генерации `<title>`, `<meta>`, canonical и разметка schema.org (JSON-LD) вынимаются из текста статьи и попадают в отдельное поле со своей кнопкой «Скопировать META». «Скопировать код» копирует только статью.

### Персональные данные не уходят в нейросеть

Перед каждым запросом к ИИ (статья, заголовок, описание картинки) персональные данные в заголовке и тексте заменяются метками: `[ФИО]`, `[телефон]`, `[e-mail]`, `[СНИЛС]`, `[паспорт]`, `[ИНН]`, `[номер карты]`, `[номер счёта]`, `[дата рождения]`, `[адрес]`. Текст в карточке при этом не меняется.

- В карточке показывается предупреждение, что найдено, а перед генерацией — подтверждение.
- В реестре такие новости помечены значком «🛡 ПДн».
- В истории записи отмечается, что и сколько удалено.

Распознавание работает по шаблонам (код — `app/services/pii.py`) и не даёт стопроцентной гарантии: необычные варианты записи может пропустить. Поэтому предупреждение предлагает просмотреть текст перед генерацией.

### Своя нейросеть и свой ключ

В «Настройках» → «Нейросеть» каждый пользователь выбирает сервис, модель и вставляет свой API-ключ. Кнопка «Проверить подключение» отправляет короткий пробный запрос.

| Сервис | Модели (примеры) | Примечание |
|---|---|---|
| DeepSeek | `deepseek-chat`, `deepseek-reasoner` | Картинки не рисует |
| Qwen (Alibaba Cloud Model Studio) | `qwen-plus`, `qwen3.8-max` | Адрес по умолчанию — международный. Можно указать адрес своего рабочего пространства. Картинки: `qwen-image-2.0-pro` |
| Google Gemini | `gemini-3.8-flash` | Картинки: `gemini-2.5-flash-image` |
| OpenAI (ChatGPT) | любая модель из документации OpenAI | |
| Anthropic (Claude) | `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5` | Температура не настраивается. Для Opus и Sonnet включён автоматический повтор запроса на другой модели Claude, если основная откажется отвечать. |
| OpenRouter | сотни моделей по одному ключу | |
| Другой OpenAI-совместимый API | любой | Нужен адрес API. Так подключаются локальные модели и сервисы со шлюзом в формате OpenAI. |

Ключи хранятся в базе в зашифрованном виде (шифрование привязано к `SECRET_KEY` из `.env`). На страницу выводится только маска вида `sk-…1234`. Если сменить `SECRET_KEY`, ключи придётся ввести заново.

### Картинки

В карточке новости картинки разделены на две колонки:
- **«Оригинал»** — картинки со страницы-источника и загруженные вручную;
- **«Сгенерировано ИИ»** — иллюстрации, нарисованные нейросетью. Выбираете промпт для картинки и нажимаете «Сгенерировать картинку». Каждый клик добавляет ещё одну картинку.

Любую картинку можно скачать в оригинальном размере кликом по миниатюре.

Нейросеть для картинок задаётся в «Настройках» → «Картинки»:
- **Отдельный сервис** (OpenAI, Gemini, Qwen или любой API в формате OpenAI Images): свой ключ, модель и размер.
- **Не указан** — запрос на картинку уходит в основную нейросеть с её ключом как дополнительный промпт. Так работает, только если основной сервис умеет рисовать (OpenAI, Gemini, Qwen или совместимый API). DeepSeek, Claude и OpenRouter картинки не создают — тогда нужен отдельный сервис.

Промпты для картинок хранятся в «Промптах» в разделе «Для картинки». В них есть подстановки `{title}`, `{original_text}` и `{generated_text}`.

Учтите, что API OpenAI и Anthropic из России напрямую не работают: серверу нужен доступ к ним или посредник вроде OpenRouter.

## Публикация в Битрикс24 → «Сайты»

Доступна пользователям, которым вы разрешили её в админке. После разрешения в «Настройках» кабинета появляется блок «Битрикс24».

**Что нужно от портала (делает сам пользователь):**
1. **Входящий вебхук.** «Разработчикам» → «Другое» → «Входящий вебхук», право **«Сайты (landing)»**. Адрес вида `https://портал.bitrix24.ru/rest/1/xxxxxxxx/` вставляется в настройки. Хранится в зашифрованном виде.
2. **Страница-шаблон статьи** в нужном сайте: шапка, подвал, оформление.
   - Блок **«HTML-код»** с меткой `%%ARTICLE%%` — сюда встанет текст статьи.
   - По желанию `%%TITLE%%` (заголовок) и `%%IMAGE%%` (первая картинка, сначала из колонки ИИ).
3. В настройках: «Загрузить сайты» → выбрать сайт и страницу-шаблон → «Сохранить».

**Кнопка «Опубликовать в Битрикс24» в карточке новости:**
1. Шаблон копируется в ту же папку (`landing.landing.copy`).
2. Метки заменяются статьёй, заголовком и картинкой (`landing.block.updatecontent`, `landing.block.uploadfile`).
3. Задаются название, адрес латиницей и SEO-поля из META-раздела (`landing.landing.update`).
4. Страница публикуется (`landing.landing.publication`).
5. Ссылка на страницу сохраняется в карточке, статус становится «Опубликована» (это можно отключить).

**Повторная кнопка «Обновить на сайте»** меняет текст на той же странице, без новой копии.

Проверено на имитации REST API Битрикс24. На настоящем портале перед массовой работой стоит опубликовать одну тестовую статью: Битрикс24 может по-своему очищать HTML в блоке.

## Локальный запуск (для разработки)

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium
.venv/bin/python -m app.cli add-user you@example.com
BASE_PATH=/publisher .venv/bin/uvicorn app.main:app --port 8090 --reload
```

Откройте http://localhost:8090/publisher/. Без `DATABASE_URL` используется SQLite в `data/publisher.db`.

```

  main.py            приложение, middleware, запуск планировщика

  templates/, static/  интерфейс
deploy/nginx-publisher.conf
Dockerfile, docker-compose.yml, .env.example
```
